# OmniSQL / Qwen2.5-Coder SFT-1+SFT-2 Ablation

This branch is intentionally based on historical commit
`2c603ffa01a00061e4d32bc157a27b1bed4eea83`, whose model-visible tool protocol is
`v2i-state-only-join-feedback-r2`. It is isolated from the current version20 tool-design branch.

## Controlled question

Using exactly the same 1,024 supervised tool actions and QLoRA hyperparameters:

1. how well do OmniSQL-7B and Qwen2.5-Coder-7B-Instruct acquire the historical table-tool protocol;
2. how much native direct-SQL BIRD accuracy does each model retain after tool SFT?

The experiment uses 512 SFT-1 actions and 512 SFT-2 actions. The SFT-2
`sft1_demo_replay` lane is excluded because those examples are already drawn from SFT-1. Both rare
decision-correction records are forced into the SFT-2 half; all other selection and final ordering
use deterministic SHA-256 priorities with seed `20260723`.
The two rare SFT-1 `set_op` targets are also retained so every historical public tool is represented.

## Primary metrics

- Direct SQL: full BIRD dev (1,534), greedy, BIRD reference set denotation (`bird-set`), before vs
  after SFT. Qwen2.5-Coder uses the controlled full-schema prompt and repetition penalty 1.05.
  OmniSQL uses its exact official prompt/inference contract.
- Historical tool acquisition: a frozen difficulty-stratified BIRD-dev 200 cohort, greedy,
  `strict-multiset`, rolling legal history (4 turns), full prompt, resident observations, at most
  30 actions. This metric is reported separately from `bird-set`.

The direct-SQL delta measures retention/catastrophic forgetting; the tool result measures whether
the SFT actually taught the interface. Absolute direct-SQL and tool percentages are not mixed.
