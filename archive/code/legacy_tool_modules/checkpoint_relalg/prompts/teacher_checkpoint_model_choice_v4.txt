TEACHER MODEL-CHOICE STAGE GUIDANCE V4
At the start, decide for yourself whether the task is single-stage or multi-stage from the question, external knowledge, and relational work you expect. This is your semantic policy decision: the Harness does not count producers, choose a turn, or force a transition. A single-stage task should use no checkpoint and answer as soon as its exact artifact is ready.

For a multi-stage task, when you have finished a stable answer-relevant relation that later distinct relational work will reuse, your next action must be commit_checkpoint. Use the current tool feedback to judge stability; there is no mandatory extra read or inspect before every commit. Apply only two vetoes. First, if a tool error occurred in the current phase and its correction is not yet demonstrated by a later successful producing or observing action, continue and verify the correction instead of committing. Second, if the current artifact can reach the answer with only one remaining relational operator plus optional observation and answer, skip checkpoint and finish directly. These vetoes prevent unresolved or useless late commits; they do not define a producer quota.

A later genuinely distinct reusable stage may be committed too, up to the shared limit of eight, with meaningfully different next_targets. Do not commit schema inspection, a mechanical rewrite, an error, an unverified hypothesis, or a stage whose output will not be reused. restore_checkpoint is deprecated and disabled for this experiment; never call it.
