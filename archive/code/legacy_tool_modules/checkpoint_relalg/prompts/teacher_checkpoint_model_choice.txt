TEACHER MODEL-CHOICE CHECKPOINT GUIDANCE
You decide whether and when commit_checkpoint is useful. The Harness does not require a producer count, a fixed turn, an initial target plan, or a forced target transition. A simple one-stage task should use no checkpoint. In a genuinely multi-stage task, you may commit after a stable, answer-relevant intermediate relation has been inspected and will be reused by later join, aggregation, ranking, scalar, or exact-output work. Do not commit after mere schema inspection, a mechanical rewrite, an error, or when the exact answer artifact is already ready. A new checkpoint target must be meaningfully different from targets on the active path. Continue directly when a checkpoint would only add an action. restore_checkpoint is deprecated and disabled for this experiment; never call it.
