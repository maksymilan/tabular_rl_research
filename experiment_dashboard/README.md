# Experiment Dashboard

Local React dashboard for browsing tabular-agent training data, training curves, evaluation cases,
and testing a served model through an OpenAI-compatible vLLM endpoint.

The overview includes both complete Qwen2.5-7B baselines:

- zero-shot direct SQL: the answer-quality reference;
- two-shot tool rollout: the base model's protocol-acquisition reference.

Each experiment exposes every registered local artifact that actually exists: train/dev JSONL,
trainer state, full/success/failure evaluation records, manifests, summaries, and related smoke
runs. The source selector is generated by the backend rather than hard-coded in React.

Records open in a structure-aware view by default:

- SFT ShareGPT records become role-separated conversations;
- tool evaluation records become step-by-step trajectories;
- direct-SQL records compare predicted SQL, gold SQL, and result samples;
- unknown JSON structures fall back to a collapsible tree and tabular array renderer.

Raw JSON remains available as a second view.

## Run

```bash
cd experiment_dashboard/frontend
npm install
npm run dev
```

In another terminal:

```bash
.venv/bin/python experiment_dashboard/backend/server.py
```

Open `http://127.0.0.1:5173`. Vite proxies `/api` to the backend on port `8787`.

The default vLLM endpoint is `http://127.0.0.1:18000/v1`, matching the repository SSH tunnel.
Override it when starting the backend:

```bash
VLLM_BASE_URL=http://127.0.0.1:8000/v1 \
  .venv/bin/python experiment_dashboard/backend/server.py
```

The Playground loads `SYSTEM_PROMPT` directly from `src/sft/protocol.py`, including the current
protocol version and hash. It also has a remote service controller:

1. Read all NewGNN GPUs, their memory/utilization, and the users holding compute processes.
2. Choose one idle GPU and a trained model registered in `data/experiments.json`.
3. Start vLLM with the experiment's LoRA adapter through `ssh NewGNN`.
4. Stop only the dashboard-managed vLLM PID after validating its owner and command.

The controller uses server port `8000`, which the existing tunnel exposes locally as `18000`.
It refuses GPUs with compute processes, more than 512 MiB used memory, or utilization above 10%.
The remote PID, metadata, and log are:

```text
/home/dengyan/tabular_rl_project/logs/dashboard_vllm.pid
/home/dengyan/tabular_rl_project/logs/dashboard_vllm.json
/home/dengyan/tabular_rl_project/logs/dashboard_vllm.log
```

Environment overrides are available as `EXPERIMENT_SSH_HOST`, `EXPERIMENT_REMOTE_ROOT`,
`EXPERIMENT_VLLM_ENV`, and `EXPERIMENT_VLLM_PORT`.

## Production-style run

```bash
cd experiment_dashboard/frontend
npm run build
cd ../..
.venv/bin/python experiment_dashboard/backend/server.py
```

The Python server serves `frontend/dist` at `http://127.0.0.1:8787`.

## Data sources

- `data/experiments.json`: editable experiment registry.
- `data/trainer_states/*.json`: local snapshots of LLaMA-Factory `trainer_state.json`.
- Repository `data/sft/*.jsonl`: training examples.
- Repository `data/results/**`: evaluation manifests and success/failure cases.

Use the refresh action in an experiment detail view to fetch the latest trainer state over
`ssh NewGNN`.
